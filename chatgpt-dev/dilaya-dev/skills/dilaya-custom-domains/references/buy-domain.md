## Buying a NEW domain through Dilaya (billed org option)

When the user has no domain yet, Dilaya can buy one for them (registrar: Route 53 Domains / Amazon Registrar) — DNS then lives in Dilaya's account, so the whole setup is automatic (no DNS records for the user to add, ever). This is a **billed org option** a platform admin enables with a purchase cap and an allowed-TLD list; billing is invoiced off-platform by Dilaya.

```
search-domain({ domain: "moncafe.fr" })      # availability + the yearly price the customer PAYS (€ HT/TTC, year one + renewal) + TLD allowed? + cap + card_required?
register-domain({ schema, domain })          # → form_url: single-use secure page for the registrant contacts
check-custom-domains()                       # follows the purchase; configures the domain END-TO-END when done
```

- **Prices are what Dilaya invoices** — euros, HT and TTC (French VAT for display), registrar cost + margin at the rate set on dilaya.eu: relay them as THE price, never mention a dollar or "AWS" price. Year one is charged at registration; the renewal price (often higher — registries discount year one) is charged every year on the anniversary. A TLD with no computable price is refused (`DOMAIN_PRICE_UNAVAILABLE`), never sold blind.
- **Who may buy, by default**: every paying organization (5 names, any TLD the registrar sells — `allowedTlds: ["*"]`), as long as a payment card is on file. A platform admin can open an org on other terms, or block it.
- The USER opens `form_url` and types the registrant contact details there — they go straight to the registrar, never through the conversation, and Dilaya does not store them. `.fr` asks the AFNIC extras (birth date for an individual).
- After submit, registration takes minutes to hours: `check-custom-domains` reports each order under `purchased_domains` and, once registered, runs the full custom-domain setup itself (certificate validation, routing incl. a REAL apex ALIAS, email DKIM) by writing the records into the domain's own zone. No user DNS action at any point.
- **The zone keeps working for SUBDOMAINS too**, however long after the purchase: `set-custom-domain({ schema, domain: "www.moncafe.fr" })` on a bought `moncafe.fr` writes its records into the same zone (`dns_managed_by_dilaya`), and `check-custom-domains` heals any that are missing (`managed_zone_records_written`). A subdomain of a domain bought by ANOTHER organization is refused (`DOMAIN_TAKEN`) — its zone is not yours to write.
- Remind the user to click the **verification email from Amazon Registrar** (ICANN rule — the domain is suspended after ~15 days otherwise); the check reports `contact_verification` until done.
- Errors: `DOMAIN_PURCHASE_NOT_ENABLED` (option off for the org), `DOMAIN_PURCHASE_NO_CARD` (a billed org with no payment card on file — relay: add a card on dilaya.eu > Abonnement, then retry; `search-domain` already flags it as `card_required: true`), `TLD_NOT_ALLOWED`, `DOMAIN_PRICE_UNAVAILABLE` (no billed price could be computed), `DOMAIN_CAP_REACHED` (relay: the admin can extend the package), `DOMAIN_NOT_AVAILABLE`, `DOMAIN_ORDER_EXISTS` (already buying, or already owned — attach with `set-custom-domain`). A `failed` order is retried by re-running `register-domain` (fresh link).
- **"Is the domain really MINE?"** — `get-domain-ownership({ domain })` answers it from the registrar: holder of record (name, organisation, masked email, country), registrar, registration/expiry dates, auto-renew, WHOIS privacy, transfer lock, and the earliest ICANN transfer date. The answer is YES by construction — the registrant form goes straight to the registrar, so the **customer** is the holder, never Dilaya. Two things to relay when asked: a public WHOIS shows nothing because purchases carry **privacy protection** (the name is theirs at the registry all the same), and there is **no registrar login to hand out** — Amazon Registrar has no customer portal, the name is administered from Dilaya's account. Their guarantee is that the domain is registered to them and can be **transferred out on request**: the authorization code is emailed to the registrant on file, never returned by any tool.
- **The domain OUTLIVES its app.** `drop-schema` detaches the app's domains (hosts stop serving) but a purchased domain stays registered to the organization with **auto-renew ON** (it keeps renewing and billing yearly — Dilaya never releases it automatically) and still counts toward the cap. It shows as `orphaned` in `check-custom-domains` / `list-custom-domains`; re-attach it to any app with `set-custom-domain({ schema, domain })` — never re-buy.
