## Consumption metering: `get-usage-report`

`get-usage-report({ include_storage?: boolean })` is the connector's **billing / tier building block** — one Dilaya connector = one org = one client, hosting several apps. Org-scoped and read-only. It returns:

- **Per app** — its database size (`dbSizeBytes`, db + WAL) and, unless skipped, its S3 storage (`storageBytes` + `storageObjects`, walked under the app's `{orgId}/{app}/` folder).
- **Org rollups** — `database.totalBytes` (all app dbs + the reserved per-org system db, whose own size is reported as `orgSystemDbBytes`), `storage` (org `totalBytes` / `totalObjects`, plus `attributed` vs `unattributed` — files not under any app folder, e.g. `exports/`), and `apps` counts (`total` / `active` / `archived`).
- **Requests this month** — each app's `requestsThisMonth` plus a `requests` rollup (`month` / `total` / `appsCounted` / `appsTotal` / `scope`). These count the app's TENANT FRONTEND requests (site + auth routes, tallied at the edge authorizer), never agent MCP calls or cron firings — `scope` says so in the payload. `requestsThisMonth: null` means there is no counter row, which is deliberately NOT the same as zero traffic (the counter only exists from 2026-08); `appsCounted` vs `appsTotal` says how much of the org the total actually covers. Since 2026-08-28 this dimension BITES: an org's monthly allowance (`maxRequestsMonth`) is enforced at the edge authorizer, which stops serving the org's tenant sites for the rest of the calendar month once the count passes the allowance plus a 5 % margin. Fully static sites are served from the edge without reaching the authorizer, so they are neither counted here nor stopped — the figure is a floor, not a total. The monthly BANDWIDTH allowance (`maxBandwidthGb`) bites the same way since 0.1.328: once the bytes CloudFront served this month pass it plus 5 %, the org's sites stop until the 1st (the owner is emailed at 80 % and 100 % first).

Sizes are point-in-time. Pass `include_storage: false` to skip the (slower) S3 object walk and return DB sizes only. A central control plane can poll each connector's report and aggregate across clients for centralized billing.
