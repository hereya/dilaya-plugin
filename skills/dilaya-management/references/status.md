## Cross-app status: `list-applications`

`list-applications()` (no args, org-scoped) returns one row per app with its lifecycle state, web-frontend state AND public URLs — `{ schema, status: "active" | "archived", archived, createdAt, archivedAt, frontendEnabled, frontendDeployed, defaultRoute, publicUrl, vanityHostUrl, customDomains }` — plus `count` / `active` / `archived` totals. `publicUrl` is THE link to show/share for an online app (active custom domain, else vanity host; null when not publicly reachable) — never build the path URL yourself, it is origin-locked (403 direct). (`frontendDeployed` = a backend Lambda is deployed, i.e. the app is ONLINE; `frontendEnabled` = the frontend flag is on but maybe not yet deployed.) It's the registry-backed superset of `list-schemas` (which returns names only): use it whenever you want to show every app's state, including an "archived" section. Apps mid-deletion, and the reserved `_console` app, are omitted. Cheap — a single registry query, no per-app database hit — so it's safe to call directly and to poll. Richer per-app detail (users, dashboards, skills, Telegram, auth) is NOT in this row; fetch it on demand with `list-users` / `list-cowork-dashboards` / `list-skills`.
